## 练习 1 ⭐｜给笔记加一个「术语表」章节（最简单）

**目标**：让生成的笔记里多出这样一段：

```markdown
## 📚 术语表

| 术语 | 解释 |
| --- | --- |
| RAG | 检索增强生成，先检索资料再让模型回答 |
| BM25 | 一种经典的文本相关性算法 |
```

**涉及知识**：Prompt 工程、JSON 数据流、模板渲染。

### 为什么要改三个地方

回忆第 02 章的"两阶段"设计：

```
字幕 → [阶段A: 模型输出 JSON] → [阶段B: 代码渲染 Markdown]
```

要让笔记多一个章节，必须让**阶段 A 的 JSON 里多一个字段**，
再让**阶段 B 把这个字段渲染出来**。这正好是理解整个数据流的最好练习。

### 步骤 1：改 Prompt，让模型输出新字段

打开 `src/llm/notes.py`，找到 `SYSTEM_STRUCT` 常量（大约在第 30 行开始）。
在 `"open_questions"` 那一行**后面**加上一行：

```python
  "open_questions": ["视频没有解答但值得思考的问题；没有就给空数组"],
  "glossary": [{"term": "专业术语", "explain": "用一句白话解释它"}]
```

然后在下面的"硬性规则"里加一条：

```python
5. glossary 只收录视频里出现过的专业名词/缩写，3-8 条，解释要白话、不要抄原文。
```

> 💡 **注意 JSON 语法**：上一行末尾的逗号别漏，最后一项后面**不要**加逗号。
> 改完可以跑一下 `python -c "import src.llm.notes"` 检查有没有语法错误。

### 步骤 2：读取这个字段

在 `render_markdown()` 函数里（约第 271 行），找到这一片：

```python
    actions = [str(a).strip() for a in (data.get("action_items") or []) if str(a).strip()]
    questions = [str(q).strip() for q in (data.get("open_questions") or []) if str(q).strip()]
```

在**下面**加一行：

```python
    glossary = data.get("glossary") or []
```

### 步骤 3：渲染成 Markdown

在 `if questions:` 那一整段（约第 386-391 行）**后面**，加上：

```python
    if glossary:
        lines.append("## 📚 术语表")
        lines.append("")
        lines.append("| 术语 | 解释 |")
        lines.append("| --- | --- |")
        for item in glossary:
            if isinstance(item, dict):
                term = str(item.get("term") or "").strip()
                explain = str(item.get("explain") or "").strip()
            else:
                term, explain = str(item).strip(), ""
            if term:
                lines.append(f"| {term} | {explain} |")
        lines.append("")
```

### 步骤 4：验证

```powershell
python tools/selftest_offline.py
```

如果 89 项全过，运行 `python run.py`，随便生成一篇笔记（**记得勾选「忽略缓存重抓」**，
否则会复用缓存，但那不影响，因为阶段 A 会重新跑），看笔记里有没有「术语表」。

**注意**：模型不一定每次都给 glossary。如果没出现，检查：
① Prompt 里的字段名和渲染代码里的 `.get("glossary")` 是否**完全一致**（大小写敏感）；
② 模型是否按要求输出了（可以在服务端日志里看）。

### 进阶：让术语表出现在思维导图里

打开同一个文件的 `_tree_from_outline()` 函数（约第 430 行），
在 `for item in (data.get("highlights") or [])` 那段后面加类似逻辑，
把 glossary 也塞进导图树的节点里。

**目标**：让思维导图的线条颜色或布局不一样。

**涉及知识**：前端第三方库的封装、调参。

打开 `web/js/mindmap.js`，找到 `init()` 函数里的这段配置：

**可以试试的改动**：

| 改什么 | 效果 |
| --- | --- |
| `spacingHorizontal: 90` → `160` | 层级之间更宽松 |
| `initialExpandLevel: -1` → `1` | 默认只展开第一层，其余折叠（长视频更好看）|
| `maxWidth: 320` → `200` | 节点变窄，整体更紧凑 |

再往下找到配色数组：

```javascript
var PALETTE = ["#2563eb", "#0d9488", "#d97706", "#7c3aed", "#db2777", "#059669", "#dc2626", "#0891b2"];
```

`colorFor()` 会根据节点路径算一个哈希值，然后取模选颜色 —— 
所以**同一个分支下的节点颜色是一致的**。你可以换成自己喜欢的色板，
或者改成只用一个颜色：

```javascript
function colorFor(path) {
  return PALETTE[0];       // 全部用第一个颜色
}
```

### 先看现成的实现

打开 `src/platforms/local_file.py`（159 行），对照 `base.py` 看，
理解 `BasePlatform` 要求的 4 个方法各自要做什么：

```python
class LocalFilePlatform(BasePlatform):
    name = "local"
    display_name = "本地视频"

    def match(self, url):        # 这个链接归我管吗？
        return is_local(url)     # url 以 "local://" 开头

    def normalize(self, url):    # 把链接拆成结构化信息
        video_id = url[len("local://"):]
        path = resolve_file(video_id)
        return {"platform": "local", "url": url, "video_id": video_id, "path": str(path), "page": 1}

    async def fetch_info(self, parsed):     # 拿元信息
```

### 你的任务：写一个"演示用"平台

新建 `src/platforms/demo.py`：

```python
"""演示平台：用一段写死的文本模拟一个视频，用来学习平台扩展机制。

URL 格式：demo://任意名字
"""

from __future__ import annotations

import time
from typing import Any, Dict, Optional

from ..core.config import Settings, get_settings
from .base import BasePlatform, PlatformError, Transcript, VideoInfo, VideoPart

SCHEME = "demo://"

FAKE_TRANSCRIPT = """[0:00] 欢迎来到演示平台，这是一段模拟的字幕文本。
[0:15] 第一，平台适配器的接口只有四个方法，实现它们就能接入新平台。
[0:40] 第二，match 负责认领链接，normalize 负责解析链接，不要混在一起。
[1:05] 第三，fetch_info 返回 VideoInfo，fetch_transcript 返回 Transcript。
[1:30] 第四，写完之后记得在 registry.py 里注册，注册后前端会自动出现。
[2:00] 以上就是演示内容，希望对你理解这个项目的架构有帮助。
"""


class DemoPlatform(BasePlatform):
    name = "demo"
    display_name = "演示平台"
    supports_audio = False      # 没有音频，不能走语音转写

    def __init__(self, settings: Optional[Settings] = None) -> None:
        self.settings = settings or get_settings()

    def match(self, url: str) -> bool:
        return (url or "").strip().startswith(SCHEME)

    def normalize(self, url: str) -> Dict[str, Any]:
        name = url.strip()[len(SCHEME):] or "未命名"
        return {"platform": self.name, "url": url, "video_id": name, "page": 1, "start_time": 0}

    async def fetch_info(self, parsed: Dict[str, Any]) -> VideoInfo:
        name = parsed["video_id"]
        return VideoInfo(
            platform=self.name,
            video_id=name,
            title=f"演示视频：{name}",
            uploader="演示账号",
            duration=150,
            description="这是演示平台生成的假数据，用于验证平台扩展机制。",
            parts=[VideoPart(index=1, title="第一部分", duration=150, cid=1)],
            url=parsed["url"],
            view_count=12345,
            like_count=678,
        )

    async def fetch_transcript(self, parsed, info, part, *, allow_asr: bool = True) -> Transcript:
        # 真实平台这里是 await 网络请求；演示平台直接返回
        return Transcript(text=FAKE_TRANSCRIPT, source="subtitle_manual", language="zh-CN")

    async def aclose(self) -> None:
        return None
```

然后在 `src/platforms/registry.py` 的 `_load_builtin()` 里注册：

### 真要接真平台时的额外工作

以 YouTube 为例，你需要：

## 开发时的 5 个避坑提醒

### 1. 中文文件编码

项目所有文件都是 **UTF-8**。用 VS Code 编辑时确认右下角显示 `UTF-8`。
如果用 PowerShell 的 `Get-Content` / `Set-Content` 改文件，很容易把编码搞坏
（真的踩过：中文全变乱码）。**改代码请用编辑器，不要用命令行重定向**。

### 2. 别在 `with db() as conn:` 外面用 conn

```python
# ❌ 错误：出了 with 块连接就关了，会报 "Cannot operate on a closed database"
with db() as conn:
    row = conn.execute("SELECT ...").fetchone()
tasks = conn.execute("SELECT ...").fetchall()      # 崩

# ✅ 正确：所有查询都在块内完成
with db() as conn:
    row = conn.execute("SELECT ...").fetchone()
    tasks = conn.execute("SELECT ...").fetchall()
```

### 3. 异步函数里别直接调用同步的慢函数

```python
# ❌ SQLite 读写会阻塞整个事件循环
task = get_task(task_id)

# ✅ 丢到线程池
task = await asyncio.to_thread(get_task, task_id)
```

判断标准：**读文件、数据库、网络（非 httpx）→ 都要套 `to_thread`**。

### 4. 新增配置项要改两个地方

假设你要加一个 `my_option` 配置：

① `src/core/config.py` 的 `Settings` 类里加字段：

```python
class Settings(BaseModel):
    ...
    my_option: str = "默认值"
```

② 如果想让它能从 `.env` 读，还要在 `_ENV_MAP` 里加映射：

```python
_ENV_MAP = {
    ...
    "MY_OPTION": "my_option",
}
```

③ 想让网页设置面板能改，还要改三个地方：
`src/webapi/schemas.py` 的 `SettingsPatch`、`web/index.html` 里加输入框、
`web/js/app.js` 的 `SETTING_FIELDS` 数组里加名字。

改完跑 `python tools/check_frontend.py` —— 它会检查"每个设置字段都有对应输入框"。

### 5. 改完记得跑自检 + 提交

## 自测题答案（来自第 02 章）

**Q1. 前端提交链接后，为什么能立刻拿到任务 ID 而不是等 2 分钟？**

因为 `routes_tasks.py` 的 `create()` 里用 `spawn_task(task["id"])` 把任务
丢到了后台 `asyncio` 任务里执行，然后**立刻 return**。
真正的处理在 `pipeline.py :: run_pipeline()` 里异步进行，
进度通过 SSE 推送给前端。

**Q2. 如果我想让笔记里多一个「术语表」章节，应该改哪个文件？**

`src/llm/notes.py`，而且要改**两个地方**：
① `SYSTEM_STRUCT` 这个 Prompt 常量（让模型输出 `glossary` 字段）；
② `render_markdown()` 函数（把 `glossary` 渲染成 Markdown 表格）。
这就是练习 1。

**Q3. 同一个视频第二次生成笔记，会跳过哪些步骤？为什么？**

跳过"抓字幕"和"下载音频 + 语音转写"。
因为 `src/core/cache.py` 用「平台+视频ID+分P+ASR配置指纹」算了一个 key，
第二次能从 `data/cache/transcripts/` 里直接读到文本，不必再走一遍最慢的步骤。

**Q4. 为什么 `get_task()` 调用要写成 `await asyncio.to_thread(get_task, task_id)`？**

因为 SQLite 的读取是同步阻塞操作。在 `async` 函数里直接调用会卡住事件循环，
导致其他 HTTP 请求（比如前端的进度查询）无法响应。
`asyncio.to_thread` 把它放到线程池执行，主事件循环就能继续处理其他请求。

3. **长文本 map-reduce**：字幕超长时自动分块摘要再合并
4. **缓存失效策略**：指纹里带上会影响结果的变量（ASR 模型、文件 mtime）
5. **异步任务 + SSE**：后台执行 + 实时进度推送 + 断线降级轮询
6. **数据库迁移**：`_migrate()` 让老用户升级不用删库，且有回归测试保护
