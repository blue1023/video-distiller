# 04 · 排错手册

> 遇到问题先别慌，按这个顺序来：**看服务端日志 → 用自检脚本定位 → 再到本文档查具体错误**。

## 通用排查三步

### 第 1 步：看日志

服务端窗口（你运行 `python run.py` 的那个窗口）会实时打印日志。**报错的第一现场就在这里。**

```powershell
# 想把日志存到文件慢慢看：
python run.py 2>&1 | Tee-Object -FilePath data\app.log
```

### 第 2 步：跑自检脚本

```powershell
python tools/selftest_offline.py     # 环境/代码问题
python tools/check_frontend.py       # 前端问题
python tools/selftest_network.py     # B 站接口问题
```

哪一步失败，问题就在哪一层。

### 第 3 步：看任务详情

网页上失败的任务卡片会显示错误原因。也可以直接调接口看：

```powershell
# 把 t_xxxx 换成你的任务 ID（在任务卡片上能看到，或调 /api/tasks 列表）
curl.exe -s "http://127.0.0.1:8848/api/tasks/t_xxxx"
```

## 一、环境类问题

### `python : 无法将"python"项识别为 cmdlet...`

**原因**：Python 没装，或装的时候没勾 "Add Python to PATH"。

**解决**：重新安装 Python 并勾选该选项，或者手动把 Python 安装目录加进系统环境变量 Path。

### `无法加载文件 ...\Activate.ps1，因为在此系统上禁止运行脚本`

**原因**：PowerShell 默认禁止执行脚本。

**解决**（执行一次即可）：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### `ModuleNotFoundError: No module named 'fastapi'`

**原因**：三种可能 —— ① 没装依赖；② 虚拟环境没激活；③ 用错了解释器。

**排查**：

```powershell
# 看当前用的是哪个 python
python -c "import sys; print(sys.executable)"
# 正确的话应该显示 ...\视频蒸馏器\.venv\Scripts\python.exe

# 如果显示的是系统 Python，说明虚拟环境没激活
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### `pip install` 卡住不动 / 下载超时

**原因**：网络问题（PyPI 在国外）。

**解决**：换国内镜像源

```powershell
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### `SyntaxError: invalid syntax` 出现在项目文件里

**原因**：Python 版本低于 3.10。项目用了 `str | None` 这种新语法。

**解决**：`python --version` 确认，低于 3.10 就升级。

## 二、大模型相关

### 网页右上角显示「⚠️ 未配置大模型」

**原因**：没填 API Key。

**解决**：设置面板填 `接口地址` + `API Key` + `主模型`，点「测试大模型连接」。

### `大模型鉴权失败` / HTTP 401

**排查清单**（按顺序检查）：

1. API Key 复制时**有没有多复制空格或换行**（最常见！）
2. Key 是不是对应你所填的服务商（DeepSeek 的 key 不能用在通义的地址上）
3. 账户余额是否为 0
4. Key 是否被删除/重置过

```powershell
# 命令行直接测一下 key 是否有效
curl.exe -s https://api.deepseek.com/v1/chat/completions `
  -H "Authorization: Bearer sk-你的key" `
  -H "Content-Type: application/json" `
  -d '{\"model\":\"deepseek-chat\",\"messages\":[{\"role\":\"user\",\"content\":\"hi\"}]}'
```

返回 `choices` 字段说明 key 正常；返回 `Authentication Fails` 就是 key 有问题。

### `大模型接口返回 404`

**原因**：接口地址填错了。

**常见错误**：

| 错误填法 | 正确填法 |
| --- | --- |
| `https://api.deepseek.com` | `https://api.deepseek.com/v1` |
| `https://api.deepseek.com/v1/chat/completions` | `https://api.deepseek.com/v1` |
| `api.deepseek.com/v1` | 要带 `https://` |

> 项目做了容错：末尾带了 `/chat/completions` 会自动处理，
> 但**服务商主域名和 `/v1` 不能少**。

### `大模型接口返回 422` 或 `400`

**原因**：通常是**模型名写错了**，或者该服务不支持 `response_format` 参数。

**解决**：

1. 确认模型名和官方文档一致（区分大小写！比如 `deepseek-chat` 不是 `DeepSeek-Chat`）
2. 换一个通用模型名试试；程序在遇到不支持 `response_format` 的服务时会自动降级重试一次

### `无法从模型输出中解析 JSON`

**原因**：模型没按要求输出 JSON（小模型更容易这样）。

**解决**：

1. 换个更强的模型（比如 `qwen-plus` 换 `qwen-max`，或直接用 DeepSeek）
2. 程序已经内置"自我修复"：会带着错误信息让模型重试一次，两次都失败才报错
3. 视频太长导致 JSON 被截断 → 试试把笔记风格改成「精简」

### `请求超时` / `ReadTimeout`

**原因**：视频太长，模型处理不过来；或者网络不稳定。

**解决**：在设置里把「超时」从 300 调到 600，或改用「精简」风格。

## 三、B 站相关

### `B 站返回 412（风控）`

**原因**：请求太频繁，或没带 Cookie 被识别为爬虫。

**解决**（按顺序试）：

1. **配 Cookie**（见 [第 03 章第 6 步](03-上手教程.md#第-6-步让字幕能抓到配-cookie)）
2. 把「请求间隔」从 1.0 调到 2.0 或 3.0
3. 把「同时运行的任务数」调回 1-2
4. 等 10-30 分钟再试（临时封禁会自动解除）

### `拿不到字幕` / `字幕接口需要登录态`

**这是最常见的"问题"，但其实是 B 站的限制。**

B 站字幕接口 `x/player/wbi/v2` 在未登录时返回 `code=-101 账号未登录`，
字幕列表恒为空。**不是代码 bug。**

**两种解决办法（任选，推荐都配）**：

1. **配 Cookie** → 能抓到人工 CC 字幕和 B 站 AI 字幕（最快最准）
2. **开语音转写** → 下载音频自己转（匿名也能下载到音频流）

诊断命令：

```powershell
# 看看这个视频到底有没有字幕
python tools/probe_bili_subtitle.py BV1xx411c7mD
```

输出里 `subtitle.subtitles=0` 且你没配 Cookie → 属正常现象。

### `视频共有 N 个分 P，p=5 不存在`

**原因**：链接里的 `?p=` 数字超过了实际分P数。

**解决**：打开视频页看看实际有几个分P，改链接再提交。

### `无法获取音频流（可能是付费/会员专享视频）`

**原因**：视频需要大会员或有其他访问限制。

**解决**：配 Cookie（用有大会员的账号登录后复制），或换个视频。

### `无法获取 B 站 WBI 签名密钥`

**原因**：`nav` 接口没返回 `wbi_img`，通常是网络被拦截或触发了风控。

**解决**：等几分钟重试；确认网络能正常访问 bilibili.com。

### `b23.tv 短链解析失败`

**原因**：短链需要跟随 302 跳转，网络不通时失败。

**解决**：在浏览器打开短链，等它跳转后复制**完整的长链接**再提交。

## 四、语音转写相关

### `未安装 faster-whisper`

```powershell
pip install faster-whisper
```

> 这个包比较大（含 PyTorch 相关依赖），装的时候耐心等。
> 如果一直装不上，改用 `openai` 转写方案。

### `本地视频没有现成字幕，必须先开启语音转写`

**原因**：本地文件必然没有字幕，只能靠转写。

**解决**：设置里把「语音转写」改成 `faster-whisper`（需先 pip 安装）或 `openai`。

### 转写特别慢

**原因**：CPU 跑 whisper 很慢。

**优化**：

1. 模型规格从 `small` 降到 `base` 或 `tiny`（准确率会下降）
2. 有 NVIDIA 显卡的话，把「本地设备」设成 `cuda`（快 10 倍以上）
3. 改用云端 `openai` 转写（花钱但快）

### `转写接口返回 400` / `转写结果为空`

**原因**：音频格式不被支持，或视频是纯音乐无人声。

**解决**：安装 ffmpeg（会自动转成标准 wav 格式），或换个有人声的视频试。

### 安装 ffmpeg（可选但推荐）

Windows 上最简单的办法是用 winget：

```powershell
winget install Gyan.FFmpeg
```

装完**重开一个 PowerShell 窗口**，执行 `ffmpeg -version` 验证。

## 五、前端 / 网页问题

### 页面打不开 / `无法连接后端服务`

**原因**：服务没启动，或端口不对。

**排查**：

```powershell
# 服务在跑吗？
curl.exe -s http://127.0.0.1:8848/api/health
# 正常返回 {"ok":true,...}
```

如果端口被占用，换个端口：`python run.py --port 9000`

### 思维导图区域空白，显示「导图库未加载」

**原因**：`web/vendor/` 里的 markmap 依赖没加载成功。

**解决**：

1. 按 `F12` 看 Console 有没有 404 错误
2. 重新下载依赖：`python tools/fetch_vendor.py`
3. 检查 `web/vendor/markmap-lib/browser/index.iife.js` 是否存在

### 导图显示但节点全挤在一起

**原因**：通常是导图节点太多（长视频章节特别碎）。

**解决**：点「适应」按钮重新布局；或者重新生成时选「精简」风格。

### 导出 PNG 失败

**原因**：浏览器跨域限制，或导图还没渲染完。

**解决**：

1. 先点一下「适应」按钮等图片渲染好再导出
2. 试试导出 `SVG`（矢量图，不会失败，也能用其他软件转 PNG）

### 进度条卡住不动

**原因**：SSE 连接断了（网络抖动）。

**解决**：程序会自动降级成每 2 秒轮询一次。还不行就按 F5 刷新页面 —— 
任务是在服务端跑的后台任务，**刷新页面不会丢任务**。

## 六、数据与文件问题

### 删除笔记时报「文件被占用」

**原因**：Windows 上文件被其他程序锁着（比如你用 Typora 打开了那个 .md）。

**解决**：关掉占用的程序，或不管它 —— 程序会把文件内容清空并改名为 `.stale`，
不影响你继续用。

### 升级代码后报 `no such column: batch_id`

**原因**：老版本数据库缺列。

**解决**：**正常情况下程序启动时会自动迁移**。如果还报错，说明启动时的
`init_db()` 没跑成功，试着：

```powershell
# 备份数据库后手动触发一次迁移
python -c "import src.core.db as d; d.init_db(); print('迁移完成')"
```

如果仍然失败，把 `data/app.db` 移走（笔记文件在 `data/notes/` 里不会丢），
重启后程序会重建数据库：

```powershell
Move-Item data\app.db data\app.db.bak
python run.py
```

> ⚠️ 移动数据库会**丢失任务和笔记的索引记录**，但 `data/notes/` 下的
> `.md` / `.xmind` 文件都还在。因为这些索引可以重建，所以这个操作是安全的。

### 想清空所有数据重新开始

```powershell
# 只清缓存（保留笔记）
curl.exe -X DELETE http://127.0.0.1:8848/api/cache

# 清空笔记 + 任务 + 上传文件（谨慎）
Remove-Item data\notes\* -Force
Remove-Item data\uploads\* -Force
Remove-Item data\app.db -Force   # 下次启动自动重建
```

## 七、还是解决不了怎么办

按这个模板收集信息，问题基本能自己定位：

```powershell
# 1. 环境信息
python --version
python -c "import sys; print(sys.executable)"

# 2. 依赖是否完好
python tools/selftest_offline.py

# 3. B 站接口是否正常
python tools/selftest_network.py

# 4. 大模型是否通
#    网页设置里点「测试大模型连接」

# 5. 完整日志（最关键）
python run.py 2>&1 | Tee-Object -FilePath data\debug.log
# 复现一次问题，然后把 data\debug.log 的最后 50 行贴出来
```

**关键信息三件套**：① 完整的报错文字 ② 你做的操作 ③ 日志最后几十行。
