## 第 1 站：`run.py` —— 程序从这里开始

只有 56 行，作用是：解析命令行参数 → 打印提示 → 启动 uvicorn 服务器 → 自动打开浏览器。

```python
import uvicorn
uvicorn.run("src.app:app", host=args.host, port=args.port, reload=args.reload)
```

`"src.app:app"` 的意思是"导入 `src/app.py` 里的 `app` 对象"。
uvicorn 是 ASGI 服务器（可以理解成 Python 世界的"Web 服务器"），
它会一直运行，把收到的 HTTP 请求交给 `app` 处理。

> 💡 你应该记住的：`run.py` 只是"启动器"，真正的应用在 `src/app.py`。

## 第 2 站：`src/app.py` —— 应用的组装车间

110 行，做四件事：

```python
# 1. 定义"启动时做什么"（lifespan）
@contextlib.asynccontextmanager
async def lifespan(app: FastAPI):
    ensure_dirs()                    # 建好 data/ 等目录
    init_db()                        # 建表 / 升级老库
    mark_pending_as_failed()         # 上次没跑完的任务标记为失败
    cleanup_dir(MEDIA_DIR)           # 清理残留的临时音频
    configure_concurrency()          # 初始化并发闸门
    yield                            # ← 服务运行期间
    # 服务关闭后的清理代码写在 yield 之后

# 2. 创建应用
app = FastAPI(title="B 站链接笔记生成工具", lifespan=lifespan)

# 3. 挂载所有路由
app.include_router(routes_tasks.router)    # /api/tasks/*
app.include_router(routes_notes.router)    # /api/notes/*
app.include_router(routes_upload.router)   # /api/upload/*
app.include_router(routes_system.router)   # /api/health、/api/settings 等

# 4. 提供前端文件
app.mount("/static", StaticFiles(directory=str(WEB_DIR)), name="static")

@app.get("/")
async def index():
    return FileResponse(WEB_DIR / "index.html")   # 访问 / 就返回网页
```

**关键概念：路由（Router）**
每个 `routes_xxx.py` 里都有一个 `router = APIRouter(prefix="/api/tasks")`，
里面用 `@router.get(...)` / `@router.post(...)` 装饰函数。
被装饰的函数就是"当有人访问这个地址时执行什么"。

理解方式：路由 = 地址 → 函数的映射表。

## 第 3 站：`src/webapi/routes_tasks.py` —— 请求的入口

打开这个文件，找到 `create()`：

```python
@router.post("", response_model=TaskOut)     # 对应 POST /api/tasks
async def create(payload: CreateTaskRequest) -> Dict[str, Any]:
    url = (payload.url or "").strip()
    if not url:
        raise HTTPException(status_code=400, detail="请填写视频链接")

    settings = get_settings()
    note_style = payload.note_style or settings.note_style or "detailed"

    # 关键三步

    #        前端拿到的 task 里 progress=0、status="pending"
```

再看 `_prepare_task()`，它做校验和落库：

```python
def _prepare_task(url, note_style, batch_id, refresh):
    settings = get_settings()
    platform = resolve(url, settings)      # ← 问注册表：这个链接谁处理？
    if platform.name == "local":
        from ..platforms.local_file import resolve_file
        resolve_file(url[len("local://"):])   # 本地文件先确认还在
    return create_task(...)                # ← 写进 SQLite
```

`payload` 的类型 `CreateTaskRequest` 定义在 `schemas.py`：

```python
class CreateTaskRequest(BaseModel):
    url: str
    note_style: Optional[str] = None
    platform: Optional[str] = None
    refresh: bool = False
```

这是 **Pydantic 模型**。它的作用是自动校验请求体：
如果前端发的 JSON 里没有 `url`，FastAPI 会直接返回 422 错误，你的代码根本不会执行。
**这是 FastAPI 最省事的地方 —— 你不用自己写 `if "url" not in data` 这种检查。**

这个文件里还有一个值得看的函数 `split_urls()`：批量提交时把多行文本解析成链接列表，
它会自动去掉重复项、支持粘贴带标题的行。逻辑很清晰，适合作为读代码练习。

### SSE 是怎么实现的（`events()` 函数）

```python
@router.get("/{task_id}/events")
async def events(task_id: str, request: Request) -> StreamingResponse:
    queue = bus.subscribe(task_id)          # ← 订阅这个任务的事件

    async def generator():
        # 先补发历史事件（防止刷新页面后进度丢了）
        for event in bus.history(task_id):
            yield f"data: {json.dumps(event, ensure_ascii=False)}\n\n"
        # 再实时推送新事件
        while True:
            event = await asyncio.wait_for(queue.get(), timeout=15.0)
            yield f"data: {json.dumps(event, ensure_ascii=False)}\n\n"

    return StreamingResponse(generator(), media_type="text/event-stream")
```

这里用了 Python 的**生成器**（`yield`）：函数不是一次性返回，而是"吐一段、停一下、再吐一段"。
SSE 协议要求的格式就是 `data: xxx\n\n`。

> 💡 `EventBus` 定义在 `src/core/db.py`，本质是 `{任务ID: [队列1, 队列2]}` 的字典。
> 后面的"章节练习"会让你给它加个功能。

## 第 4 站：`src/pipeline.py` —— 心脏

**这是全项目最该读懂的一份文件。** 它的核心函数是 `run_pipeline()`（第 163 行开始），
就是把第 1 章那张流程图用代码写了一遍。去掉注释和进度推送，骨架是这样的：

```python
async def run_pipeline(task_id: str) -> Artifacts:
    settings = get_settings()
    task = await asyncio.to_thread(get_task, task_id)      # 从数据库读任务

    # ── 1. 解析链接 ──────────────────────────────
    platform = resolve(url, settings)          # 找平台
    parsed = platform.normalize(url)           # 拆出 video_id / page

    # ── 2. 拿视频信息 ────────────────────────────
    info: VideoInfo = await platform.fetch_info(parsed)

    # 从分P列表里挑出用户要的那一P
    part = next((p for p in info.parts if p.index == page), None)

    # ── 3. 字幕（先查缓存）──────────────────────
    transcript = None
    if not refresh:
        cached = cache.load(info.platform, info.video_id, part.index, extra=cache_extra)
        if cached is not None:
            transcript = cached                # 命中！跳过下载和转写

    if transcript is None:
        transcript = await platform.fetch_transcript(parsed, info, part, allow_asr=can_asr)
        cache.store(...)                       # 存进缓存，下次就不用重抓了

    # ── 4. 让大模型把字幕变成结构化笔记 ──────────
    note = await generate_note(
        transcript.text, info, part,
        transcript_source=transcript.source,
        note_style=note_style,
        settings=settings,
    )

    # ── 5. 落盘 + 登记 ──────────────────────────
    artifacts = await asyncio.to_thread(save_artifacts, task_id, info, part, note, transcript)
    return artifacts
```

### 三个新手容易困惑的点

**① `await asyncio.to_thread(...)` 是什么？**

SQLite 的读写是"阻塞"的（执行期间 CPU 干等着），如果直接在 `async` 函数里调用，
会卡住整个事件循环，导致其他请求也无法响应。
`asyncio.to_thread()` 把它丢到线程池里执行，这样主循环就不被堵住了。

> 简单记忆：**异步世界里调用同步的慢函数，就套一层 `to_thread`。**

**② 为什么要 `raise PlatformError(...)` 而不是直接报错？**

`_run_guarded()`（第 108 行）会捕获所有异常，把错误信息写进任务的 `error` 字段，
再通过 SSE 推给前端显示。所以流水线里**可以放心抛异常** —— 它一定会变成用户看得懂的提示。

`_humanize_error()` 还会把技术错误翻译成人话，比如把
`401 Unauthorized` 翻译成「大模型鉴权失败，请检查 API Key 与接口地址」。

**③ `Artifacts` 是什么？**

一个 `@dataclass`（数据类），用来把"产物的路径"打包返回：

```python
@dataclass
class Artifacts:
    note_id: str
    markdown: str
    md_path: Path
    tree: Dict[str, Any] = field(default_factory=dict)
    mindmap_path: Optional[Path] = None
    xmind_path: Optional[Path] = None
    opml_path: Optional[Path] = None
```

`@dataclass` 是 Python 提供的语法糖，自动帮你生成 `__init__`，比手写省事。

## 第 5 站：`src/platforms/base.py` —— 抽象接口

115 行，是**最值得学习的设计模式**（面向接口编程）。核心就一个抽象类：

```python
@dataclass
class VideoInfo:          # 视频元信息
    platform: str
    video_id: str
    title: str
    uploader: str = ""
    duration: int = 0
    parts: List[VideoPart] = field(default_factory=list)
    ...

@dataclass
class Transcript:         # 字幕/转写结果
    text: str
    source: str           # subtitle_manual | subtitle_ai | asr_openai | ...
    segments: List[Dict[str, Any]] = field(default_factory=list)

class BasePlatform(abc.ABC):
    name: str = "base"
    display_name: str = "通用平台"

    @abc.abstractmethod
    def match(self, url: str) -> bool: ...

    @abc.abstractmethod
    def normalize(self, url: str) -> Dict[str, Any]: ...

    @abc.abstractmethod
    async def fetch_info(self, parsed) -> VideoInfo: ...

    @abc.abstractmethod
    async def fetch_transcript(self, parsed, info, part, *, allow_asr=True) -> Transcript: ...
```

`abc.ABC` + `@abc.abstractmethod` 的意思是：
**子类必须实现这些方法，否则不能被实例化**（会直接报错）。
这是一种"强制契约" —— 保证流水线调用任何一个平台时，这 4 个方法一定存在。

然后 `registry.py`（84 行）负责"哪个链接归哪个平台"：

```python
def resolve(url, settings=None) -> BasePlatform:
    for name in _ORDER:                     # 按注册顺序试
        platform = get_platform(name, settings)
        if platform.match(url):             # 谁认领就是谁
            return platform
    raise PlatformError("没有平台能处理这个链接…")
```

## 第 6 站：`src/llm/notes.py` —— Prompt 工程 + 模板

579 行，前半部分是 Prompt 文本（`SYSTEM_STRUCT` 等常量），后半部分是渲染逻辑。

### 阶段 A：把字幕变成 JSON

看 `SYSTEM_STRUCT` 这个 Prompt 常量，它对模型提出了硬性要求：

```
输出严格为 JSON 对象，结构如下（字段名必须完全一致）：
{
  "title": "笔记标题…",
  "one_sentence": "一句话总结…",
  "summary": "200-400 字的整体摘要…",
  "keywords": [...],
  "outline": [{"heading": "...", "level": 2, "start": 0, "end": 120, "points": [...]}],
  "highlights": [...],
  "quotes": [{"text": "...", "time": "12:34"}],
  ...
}
硬性规则：
1. outline 必须覆盖视频从头到尾的内容，章节之间时间不重叠，start/end 为秒数
2. points 里的每一条都要具体，禁止"讲解了相关内容"这类空话
```

**写 Prompt 的两个实用技巧**（可以直接抄）：

1. **给出完整的 JSON 示例**，而不是用文字描述字段 —— 模型的模仿能力远强于理解能力。
2. **明确说"不要输出 markdown 代码块围栏"** —— 否则模型很喜欢包一层 ```` ```json ````。

### 长视频怎么办：`map-reduce`

如果字幕超过 3 万字（约 1 小时视频），一次塞给模型会超出上下文窗口。
解决思路和 MapReduce 一样：

```
把字幕切成 6 块
  ↓ map：6 块并发送给模型，各自输出"小结"  （用 asyncio.Semaphore(3) 限制并发 3 个）
  ↓ reduce：把 6 份小结合并，再让模型输出最终的结构化笔记
```

代码在 `_structure_transcript()`。超过 8 块时还会先"两两粗合并"，避免合并请求本身太长。

### 阶段 B：JSON → Markdown

`render_markdown()` 是纯字符串拼接，没有任何魔法：

```python
lines.append(f"# {title}")
lines.append("")
lines.append(f"> **一句话总结**：{one_sentence}")
for index, section in enumerate(outline, 1):
    lines.append(f"### {index}. {section['heading']}")
    lines.append(f"⏱ [{span}]({_chapter_link(info, part, start)})")   # 带时间戳跳转的链接
    for point in section["points"]:
        lines.append(f"- {point}")
```

`_chapter_link()` 负责拼出 `https://www.bilibili.com/video/BVxxx?p=1&t=125` 这种链接。

> 💡 想改笔记排版？直接改 `render_markdown()` 里的字符串就行，不用碰 Prompt。
> 第 5 章的练习会让你做这件事。

## 第 7 站：`src/core/` —— 四个基础设施文件

### `config.py`（231 行）：配置从哪来

优先级：**环境变量 > `data/settings.json`（网页设置写入的）> 代码默认值**

```python
def get_settings(refresh: bool = False) -> Settings:
    global _cached
    with _lock:
        if _cached is None or refresh:
            _cached = Settings(**_load_overrides())   # 读盘 + 合并 + 校验
        return _cached
```

注意 `_cached` —— 配置读一次就缓存起来，不然每次请求都读文件很浪费。
但网页改了设置后要立刻生效，所以 `save_settings()` 里会 `get_settings(refresh=True)`。

还有一个细节值得学：`public()` 方法会在返回给前端前把 API Key 打码成 `***`：

```python
def public(self) -> Dict[str, Any]:
    data = self.model_dump()
    for key in ("llm_api_key", "asr_api_key", "bili_cookie"):
        data[key] = "***" if data.get(key) else ""
    return data
```

**永远不要把密钥原文发给前端**，哪怕是自己用的工具。

### `db.py`（398 行）：数据怎么存

三张表：`tasks`（任务）、`notes`（笔记）、`batches`（批次）。

```python
CREATE TABLE IF NOT EXISTS tasks (
    id TEXT PRIMARY KEY,
    url TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending',   -- pending/running/success/failed/cancelled
    progress REAL NOT NULL DEFAULT 0,
    ...
);
```

两个值得注意的地方：

**① 连接管理用上下文管理器**

```python
@contextmanager
def db():
    conn = _connect()
    try:
        yield conn
        conn.commit()      # 正常结束就提交
    finally:
        conn.close()       # 无论怎样都关闭
```

用法是 `with db() as conn: ...`。**注意所有查询都必须写在 `with` 块里面** ——
出了块连接就关了。项目里真的踩过这个坑（`get_batch()` 曾经在块外查询，直接崩了）。

**② 数据库升级（迁移）**

`_migrate()` 会在老库上补上后来新增的列：

```python
def _migrate(conn):
    existing = {row["name"] for row in conn.execute("PRAGMA table_info(tasks)")}
    additions = {"batch_id": "TEXT", "refresh": "INTEGER DEFAULT 0", ...}
    for column, definition in additions.items():
        if column not in existing:
            conn.execute(f"ALTER TABLE tasks ADD COLUMN {column} {definition}")
```

**这是真实项目必须做的事**：你已经生成了 20 篇笔记，总不能因为加了新功能就把库删了重建。
`tools/selftest_offline.py` 里有一个专门的老库升级回归测试。

### `cache.py`（173 行）：转写缓存

核心是一个哈希指纹：

```python
def fingerprint(platform, video_id, part=1, *, extra="") -> str:
    raw = f"{platform}|{video_id}|{part}|{extra}"
    return hashlib.sha1(raw.encode("utf-8")).hexdigest()[:20]
```

文件存为 `data/cache/transcripts/<指纹>.json`。
`extra` 参数里塞的是"影响转写结果的东西"（ASR 模型名、本地文件的 mtime），
这样换模型或换文件时缓存自动失效。

### `utils.py`（360 行）：工具箱

挑三个最有意思的看：

**`safe_filename()`** —— 把视频标题变成合法文件名。
Windows 不允许 `\ / : * ? " < > |`，所以要替换掉：

```python
_ILLEGAL = re.compile(r'[\\/:*?"<>|\r\n\t]+')
def safe_filename(text, max_length=80, fallback="note"):
    text = _ILLEGAL.sub("_", text)
    ...
```

**`tree_to_xmind()`** —— 生成 `.xmind` 文件。
XMind 文件其实就是一个 zip，里面装着 JSON：

```python
with zipfile.ZipFile(buffer, "w", zipfile.ZIP_DEFLATED) as zf:
    zf.writestr("content.json", json.dumps(content, ensure_ascii=False))
    zf.writestr("metadata.json", ...)
    zf.writestr("manifest.json", ...)
```

**没有任何第三方依赖**，用标准库 `zipfile` 就搞定了。

**`split_transcript()`** —— 智能切块。
不能按固定字数硬切，否则会把句子拦腰截断，所以优先在句号、换行处切，
并保留 200 字重叠防止上下文断裂。

### `api.js`（103 行）—— 最易懂，建议第一个看

### `app.js`（935 行）—— 页面逻辑，最长的一份

结构是"一个立即执行函数 + 一堆小函数"：

```javascript

  function showNote(note) { ... }              // 显示笔记
  async function boot() { ... }                // 启动入口

```

**SSE 订阅**（`subscribe()`）值得看，对应后端的 `events()`：

```javascript
function subscribe(taskId) {
  var source = new EventSource("/api/tasks/" + taskId + "/events");
  source.onmessage = function (event) {
    var data = JSON.parse(event.data);
    upsertTask(data);                    // 更新任务卡片
    if (data.status === "success") { ... }  // 成功了就打开笔记
  };
  source.onerror = function () {          // 流断了退回轮询
    closeSource(taskId);
    startPolling();
  };
}
```

注意 `onerror` 里的**降级策略**：SSE 断了就用每 2 秒轮询一次的方式兜底。
真实项目里不能假设某个技术一定可靠。

### `mindmap.js`（268 行）—— 思维导图

它把 markmap 这个第三方库封装成 6 个方法，`app.js` 只调用这 6 个：

```javascript
window.Mindmap = { init, render, fit, rescale, exportSvg, exportPng, isAvailable };
```

**这是"封装"的价值**：哪天想把 markmap 换成 ECharts，只改这一个文件，
`app.js` 一行都不用动。
